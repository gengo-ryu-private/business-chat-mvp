# テスト方針

## 目的

主要機能、画面上の制御、利用フロー、Firestoreのアクセス制御を、適切な粒度で確認する方針を定義する。

すべてを網羅するのではなく、認証、テナント分離、権限、メッセージ投稿までの主要なリスクを優先する。

## テスト種別

| 種別                           | ツール                                            | 主な対象                                 |
| ------------------------------ | ------------------------------------------------- | ---------------------------------------- |
| 関数テスト                     | Vitest                                            | 入力検証、権限判定、データ生成           |
| コンポーネントテスト           | React Testing Library                             | 表示、入力、操作、ユーザー種別による制御 |
| E2Eテスト                      | Playwright、Firebase Emulator                     | 管理者・一般ユーザーの主要フロー         |
| Firestore Security Rulesテスト | Firebase Emulator、`@firebase/rules-unit-testing` | テナント分離、作成権限、入力制約         |

## 関数テスト

画面やFirebaseとの通信に依存しない処理を確認する。

- 必須入力、メールアドレス、文字数、参加コードの検証
- 管理者判定とチャンネル作成可否
- 参加コード生成
- 日時表示の変換
- 登録時のテナント・ユーザーデータ生成
- Firestore保存用データ生成

## コンポーネントテスト

ユーザー操作に近い形で、コンポーネントの表示と振る舞いを確認する。

- ログインフォームの入力エラー
- 登録方法によるユーザー登録フォームの切り替えと入力エラー
- ユーザー種別によるチャンネル作成フォームの表示制御
- チャンネル作成フォームの文字数検証
- メッセージ投稿フォームの入力検証と送信内容
- メッセージ一覧の表示と空状態
- ユーザー種別による参加コードの表示制御

Firebaseとの通信はモックし、コンポーネントの責務に限定して確認する。

## E2Eテスト

Firebase Emulatorを使用し、以下を一連の利用フローとして確認する。

1. 管理者ユーザーが新規テナントを作成する
2. 管理者ユーザーがチャンネルを作成し、参加コードを確認する
3. 一般ユーザーが参加コードで既存テナントに参加する
4. 一般ユーザーにチャンネル作成フォームが表示されないことを確認する
5. 一般ユーザーがメッセージを投稿する
6. 管理者ユーザーの画面へメッセージがリアルタイムに反映されることを確認する
7. ログアウト後に認証後の画面へアクセスできないことを確認する

## Firestore Security Rulesテスト

Firebase Emulatorを使用し、画面上の制御を回避しても不正なアクセスや書き込みが拒否されることを確認する。

- 未ログインユーザーによる読み取りの拒否
- 自分以外のユーザー情報と所属テナント外データへのアクセス拒否
- 管理者ユーザーによるチャンネル作成の許可
- 一般ユーザーによるチャンネル作成の拒否
- 所属テナント内の既存チャンネルへのメッセージ投稿の許可
- 所属テナント外へのメッセージ投稿の拒否
- クライアントによる`users`と`tenants`の作成・更新・削除の拒否
- チャンネルとメッセージの文字数制約

## 実行コマンド

```bash
npm run test
npm run test:rules
npm run test:e2e
```

## テスト対象外

- Firebase AuthenticationやFirestore自体の内部挙動
- MVPに含めていない機能
- ブラウザごとの細かな表示差異
- レスポンシブ表示の網羅確認
- 大量データ、負荷、セキュリティ診断レベルの検証
