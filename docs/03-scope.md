# MVPスコープ

## このドキュメントの目的

このドキュメントでは、業務用チャットアプリMVPで実装する範囲と、初期MVPでは実装しない範囲を明確にする。

`docs/02-users.md` で整理した想定ユーザーと課題をもとに、MVPでどの課題をどこまで解決するかを定義する。

## スコープ定義の方針

このMVPでは、機能数を増やすことよりも、想定ユーザーの課題に対して必要な最小限の機能を実装することを重視する。

具体的には、以下の方針でスコープを定義する。

- 小規模組織の情報共有課題を解決する
- 業務用アプリとして必要な基本構造を含める
- 認証、テナント管理、チャンネル管理、メッセージ管理を実装する
- 初期MVPでは高度なチャット機能は扱わない
- 設計、実装、テストまで完了できる範囲に絞る

## 想定課題とMVPでの対応

`docs/02-users.md` で整理した課題に対して、MVPでは以下のように対応する。

| 想定課題                                       | MVPでの対応                                      |
| ---------------------------------------------- | ------------------------------------------------ |
| 連絡内容が口頭、メール、個人チャットに分散する | チャンネル内にメッセージを集約する               |
| 過去のやり取りを確認しづらい                   | チャンネルごとにメッセージ一覧を表示する         |
| 話題ごとに情報を整理しづらい                   | 管理者ユーザーがチャンネルを作成できるようにする |
| 誰がいつ発言したか分かりづらい                 | メッセージに投稿者名と投稿日時を表示する         |
| 組織単位で情報を管理しづらい                   | テナント単位でデータを分離する                   |
| 関係者以外への情報共有を避けたい               | 認証済みユーザーだけが利用できるようにする       |
| 新しいメンバーがチームに参加しづらい           | 参加コードで既存テナントに参加できるようにする   |

## MVPで実現する基本フロー

このMVPでは、以下の利用フローを実現する。

1. ユーザーがアカウントを作成する
2. ユーザーが新規テナントを作成する、または既存テナントに参加する
3. ユーザーがログインする
4. ユーザーが所属テナントのチャンネル一覧を確認する
5. 管理者ユーザーがチャンネルを作成する
6. ユーザーがチャンネル内でメッセージを投稿する
7. ユーザーがチャンネル内のメッセージ一覧を確認する

この流れにより、単なるチャット画面ではなく、業務アプリとして必要な認証・組織管理・情報共有の基本構造を示す。

## MVPで実装する機能

## 1. 認証機能

### 実装すること

- ユーザー登録
- ログイン
- ログアウト
- ログイン状態に応じた画面制御

### 対応する課題

関係者以外への情報共有を避けるため、認証済みユーザーだけがアプリを利用できるようにする。

## 2. テナント管理機能

### 実装すること

- 新規テナント作成
- 参加コードによる既存テナント参加
- ログインユーザーとテナントの紐付け
- 所属テナント情報の表示
- テナント単位のデータ分離

### 対応する課題

組織単位で情報を管理できるようにするため、テナント単位でデータを分離する。

## 3. チャンネル管理機能

### 実装すること

- チャンネル作成
- チャンネル一覧表示
- チャンネル詳細表示
- 管理者ユーザーのみチャンネル作成可能にする

### 対応する課題

話題ごとに情報を整理できるようにするため、チャンネル単位で会話の場を分ける。

## 4. メッセージ機能

### 実装すること

- メッセージ投稿
- メッセージ一覧表示
- 投稿者名の表示
- 投稿日時の表示

### 対応する課題

口頭や個別連絡で分散していた業務連絡を、チャンネル内のメッセージとして残せるようにする。

また、投稿者名と投稿日時を表示することで、誰がいつ発言した内容なのかを確認できるようにする。

## 5. 基本的な権限制御

### 実装すること

- 未ログインユーザーは認証後の画面にアクセスできない
- ユーザーは所属テナントのデータだけを閲覧できる
- 管理者ユーザーだけがチャンネルを作成できる
- 一般ユーザーはチャンネル閲覧とメッセージ投稿のみ行う

### 対応する課題

業務情報を関係者だけで扱えるようにするため、認証状態、所属テナント、ユーザー種別に応じて操作範囲を制御する。

## 6. テスト

### 実装すること

- 主要なロジックの単体テスト
- 主要なUIコンポーネントのテスト
- 基本的なユーザー操作のE2Eテスト

### 対応する課題

転職用ポートフォリオとして、単に動くアプリを作るだけではなく、品質を意識して実装できることを示す。

## MVPでは実装しない機能

初期MVPでは、以下の機能は実装対象外とする。

- ファイル添付
- 画像投稿
- メンション
- リアクション
- スレッド返信
- ダイレクトメッセージ
- 通知
- 既読管理
- メッセージ検索
- メッセージ編集
- メッセージ削除
- チャンネル編集
- チャンネル削除
- ユーザー招待メール送信
- ユーザー削除
- 管理者権限の付与・剥奪
- 複数管理者
- 複数テナント切り替え
- チャンネルごとの閲覧権限
- チャンネルごとの投稿権限
- 外部サービス連携
- 監査ログ
- 管理者向け詳細設定

## MVPから除外する理由

初期MVPでは、チャットアプリとして便利な機能をすべて実装することは目的としない。

ファイル添付、メンション、通知、既読管理などは実務上は重要だが、初期MVPに含めると実装範囲が広がりすぎる。

このポートフォリオでは、まず以下を優先する。

- 想定ユーザーの主要課題に対応すること
- 業務アプリとして成立する最小構成を作ること
- 認証、テナント管理、チャンネル管理、メッセージ管理を一通り実装すること
- 設計意図を説明できること
- 主要機能を完成させること
- テストまで実装すること

そのため、追加機能は将来的な拡張候補として扱う。

## MVPの対象外だが将来的に検討する機能

将来的な拡張候補として、以下の機能を検討する。

| 機能                     | 追加する場合の目的                           |
| ------------------------ | -------------------------------------------- |
| ファイル添付             | チャンネル内で資料を共有できるようにする     |
| メンション               | 特定ユーザーに発言を届けやすくする           |
| 通知                     | 新しい投稿や重要な連絡に気づきやすくする     |
| 既読管理                 | 誰が確認済みか把握できるようにする           |
| メッセージ検索           | 過去の情報を探しやすくする                   |
| スレッド返信             | 特定の話題に対する返信を整理しやすくする     |
| チャンネルごとの権限管理 | 部署や関係者ごとに閲覧範囲を制御する         |
| ユーザー招待メール       | 参加コード共有より自然な招待フローにする     |
| 複数テナント所属         | 複数組織に所属するユーザーを扱えるようにする |

## 完成とみなす条件

このMVPは、以下の状態になった時点で完成とみなす。

- ユーザーが新規登録できる
- ユーザーがログイン・ログアウトできる
- 新規テナントを作成できる
- 参加コードで既存テナントに参加できる
- ログイン後、自分の所属テナントにアクセスできる
- 管理者ユーザーがチャンネルを作成できる
- 一般ユーザーはチャンネルを作成できない
- 所属テナント内のチャンネル一覧を表示できる
- チャンネル詳細画面を表示できる
- チャンネル内でメッセージを投稿できる
- 投稿されたメッセージが一覧表示される
- メッセージに投稿者名と投稿日時が表示される
- 所属テナント外のデータにアクセスできない
- 主要な処理に対するテストが存在する
- READMEと設計ドキュメントから、アプリの目的・課題・スコープ・技術構成を説明できる

## MVPスコープのまとめ

このMVPでは、小規模組織における情報共有の分散、話題整理の難しさ、過去のやり取りの確認しづらさを解決するために、業務用チャットアプリの最小構成を実装する。

実装対象は、認証、テナント管理、チャンネル管理、メッセージ投稿・表示、基本的な権限制御に絞る。

多機能なチャットツールを作ることではなく、業務課題から必要な機能を定義し、設計・実装・テストまで一貫して進めることを重視する。
